# Equal-compute allocation search: implemented baselines and next KWS study

`netsurf/equal_compute_search.py` implements two distinct mask-selection policies over a fixed candidate universe and cardinality. `random_search` draws a uniform legal fixed-budget mask with replacement for each proposal and retains the lowest measured selection risk. `greedy_swap` starts at the same mask, samples one protected and one unprotected coordinate uniformly, and accepts only a strict measured risk reduction. Both spend one query on the common initial mask and then the same prespecified number of proposals. Ties retain the incumbent. Seeds, proposal traces, risk values, accepted states, query counts, evaluation cost and wall time are recorded. The callback supplied by a real benchmark must use the same frozen input cohort and master fault fields for every query. Held-out evaluation requires a distinct field/input identity and never feeds risk back into search. A random search that selects the best measured mask is therefore separate from a single random-ranking baseline.

The pure search layer has deterministic pseudo-Boolean tests for signed effects, a pair interaction, initial-mask equality, fixed budget, matched query counts, independent final identity, reproducibility, and a meaningful 72-bit/24-protected scaling fixture. It does not implement RL or a guided optimizer.

## Read-only M9.6 engineering exercise

`netsurf/equal_compute_m96.py` reads the immutable M9.6 manifest SHA-256 `46674ad4f90e8bc49fcee3ef826bbb57130005f239d192700cd09d8f106d3ff3` and verifies each selection receipt, payload digest, response-table checksum and exact 15-mask table. It uses **all twelve** originally sampled K=6 pools, with two S5-protected and four S5-unprotected candidates each; there is no resampling. For each pool, the first 16 of the already saved 32 background fields define the retrospective selection risk and the other 16 define a held-out background diagnostic. Three prespecified search seeds, 901/902/903, run each method at ten table queries, with the same initial S5 mask. The two halves share the same input clips. They were both part of a historical selection experiment and were already available when this exercise was designed, so the second half is not a prospective publication final set. The original M9.6 isolated mask used all 32 fields and is deliberately not called an independent comparator for this split.

The 12 tables required 12 × 32 × 64 = 24,576 candidate-state model requests in the historical M9.6 experiment. This new retrospective exercise makes **zero** new model requests and **zero** new clip inferences; each search makes ten saved-table lookups. The result is an algorithm and provenance check, not an equal-inference prospective comparison. Its new evidence bundle is written under `workspace/runs/m96_equal_query_retrospective_v1`; no M9.6 source or finalized files are changed.

The four comparison categories are original static S5, exact isolated-bit selection on the 64 selection clips, equal-query random search, and equal-query greedy conditional swaps. The isolated score is each candidate's exact one-bit cross-entropy change from the clean S5 context on selection clips, retaining harmful as well as beneficial signs; it is an isolated reference, not a conditional optimum. The search policies start from the same 24 S5 bits, use three prespecified proposal seeds each, and spend exactly **64 mask-risk queries per seed**, including the common initial mask. Each query uses the same **64 independent selection master fields**, the same 64 clips, and BER 0.01 over the complete eligible bit universe with ideal suppression under that query's fixed global mask. Candidate bits and outside-network faults both follow Bernoulli(0.01); a master field is shared across every queried mask. Query traces record proposed/applied/suppressed events, full schedules, restoration and actual model-call costs. Static S5 and isolated scoring have lower and separately reported selection cost; only random and greedy are an equal-compute search comparison. No saved M9.6 response or final field is used to select a winner.

Selection seeds are reserved as `970101–970103` for random search, `970201–970203` for greedy swap, and `970301 + 1,000,003 × j` for selection fields `j=0…63`. Final fields use independent seeds `970501 + 1,000,003 × j` for `j=0…127`. The exact random-number implementation, candidate schedule mapping and source hashes must be included in a frozen executable manifest before any selection run. All six search winners and the isolated mask must be sealed before a final field. Final evaluation uses 128 new master fields on the shared 416 clips and evaluates the static, isolated and six search-selected masks on each field. Duplicate selected masks remain named policy arms and are counted as distinct requests for the conservative cost envelope; verified identical-state reuse may reduce actual authoritative calls, with the reuse disclosed.

### Cost and inference scope

Six search trajectories × 64 queries × 64 selection fields require **24,576 mask/model requests** and **1,572,864 clip inferences**. The 72 isolated-bit calls plus one clean call add 73 requests and 4,672 clip inferences. Final evaluation has at most 128 × 8 = **1,024 requests** and **425,984 clip inferences**. The complete conservative envelope is **25,673 requests and 2,003,520 clip inferences**, plus adapter initialization/reference overhead. Historical M9.6 measured 24,660 selection requests, 1,578,240 selection clip inferences and 5,840.14 s across 12 members; its final members took 7,461.99 s for a much larger 9,437,184-clip upper bound. These are reference measurements, not a throughput guarantee for the new search. Provision about **3 foreground hours and at least 2 GiB RAM** initially, then measure one bounded selection-query pilot on previously exposed inputs before final resource freeze. The 64 candidate-fault fields are likely sparse at p=0.01; unstable or null selection is an allowed outcome and field counts must not be raised after seeing final effects.

The prespecified primary contrast is the paired final cross-entropy difference **greedy minus random**, averaging the three fixed proposal seeds within each final field; negative favors greedy. Use a two-sided 10,000-replicate field bootstrap interval and 10,000 paired sign-flip draws at analysis seed `970901`, with no grid search. The secondary family has exactly four two-sided contrasts: random minus S5, greedy minus S5, random minus isolated, and greedy minus isolated, each averaged over its three seeds; apply Holm adjustment across those four sign-flip p-values. Preserve all six seed-specific masks and effects in sensitivity tables. Report accuracy separately, favorable/adverse/tied field counts, median and 10% trimmed field differences, maximum absolute field difference, nonfinite/failure counts and the effect after omitting the largest absolute field as heavy-tail diagnostics. The single fixed 72-bit panel supports inference conditional on that panel and final input cohort; its 12 historical K=6 components are **not** independent cross-pool replicates for this global search. Shared final clips and fault fields preserve dependence among all policies. No whole-model optimality, cross-pool generalization or physical reliability claim follows.

This is a prospective **protocol**, not yet a frozen executable campaign. The source adapter must bind the exact ordered labels and encoded-input hashes for both windows, enforce the seed and all-selection-before-final gates, create immutable verified receipts and an offline exporter. The final window is reserved for this future study, but no final input or fault outcome is accessed here. Final execution cannot begin until the manifest and selection seal pass those checks. The retrospective twelve-pool table exercise below remains engineering evidence only.
