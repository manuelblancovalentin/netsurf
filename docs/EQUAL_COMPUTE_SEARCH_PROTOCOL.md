# Equal-compute allocation search: implemented baselines and next KWS study

`netsurf/equal_compute_search.py` implements two distinct mask-selection policies over a fixed candidate universe and cardinality. `random_search` draws a uniform legal fixed-budget mask with replacement for each proposal and retains the lowest measured selection risk. `greedy_swap` starts at the same mask, samples one protected and one unprotected coordinate uniformly, and accepts only a strict measured risk reduction. Both spend one query on the common initial mask and then the same prespecified number of proposals. Ties retain the incumbent. Seeds, proposal traces, risk values, accepted states, query counts, evaluation cost and wall time are recorded. The callback supplied by a real benchmark must use the same frozen input cohort and master fault fields for every query. Held-out evaluation requires a distinct field/input identity and never feeds risk back into search. A random search that selects the best measured mask is therefore separate from a single random-ranking baseline.

The pure search layer has deterministic pseudo-Boolean tests for signed effects, a pair interaction, initial-mask equality, fixed budget, matched query counts, independent final identity, reproducibility, and a meaningful 72-bit/24-protected scaling fixture. It does not implement RL or a guided optimizer.

## Read-only M9.6 engineering exercise

`netsurf/equal_compute_m96.py` reads the immutable M9.6 manifest SHA-256 `46674ad4f90e8bc49fcee3ef826bbb57130005f239d192700cd09d8f106d3ff3` and verifies each selection receipt, payload digest, response-table checksum and exact 15-mask table. It uses **all twelve** originally sampled K=6 pools, with two S5-protected and four S5-unprotected candidates each; there is no resampling. For each pool, the first 16 of the already saved 32 background fields define the retrospective selection risk and the other 16 define a held-out background diagnostic. Three prespecified search seeds, 901/902/903, run each method at ten table queries, with the same initial S5 mask. The two halves share the same input clips. They were both part of a historical selection experiment and were already available when this exercise was designed, so the second half is not a prospective publication final set. The original M9.6 isolated mask used all 32 fields and is deliberately not called an independent comparator for this split.

The 12 tables required 12 × 32 × 64 = 24,576 candidate-state model requests in the historical M9.6 experiment. This new retrospective exercise makes **zero** new model requests and **zero** new clip inferences; each search makes ten saved-table lookups. The result is an algorithm and provenance check, not an equal-inference prospective comparison. Its new evidence bundle is written under `workspace/runs/m96_equal_query_retrospective_v1`; no M9.6 source or finalized files are changed.

## Prespecified larger KWS scaling design, pending final exposure

The exact union of the twelve frozen pools has **72 unique bit identities** and exactly **24** originally S5-protected bits. A 24-for-24 restricted swap therefore preserves the global S5 22,016-of-176,128 protection cardinality while giving the search a substantially larger allocation space than one six-bit pool. The M9.6 manifest and all candidate hashes remain binding; no favorable pool is chosen. The proposed comparison starts from the 24 S5 bits and uses random search and greedy swap with three independent proposal seeds each, 64 mask queries per seed, common selection input clips and background fields, and independent final fields. Static S5 and a selection-only exact isolated ranking are controls. Exact isolated scoring on 72 bits is affordable, but its sample cohort and fault-context interpretation must be specified before running.

A provisional budget for **16 selection fields × 64 clips per mask query** is 384 search mask measurements, 6,144 model requests and 393,216 clip inferences. A 72-bit isolated screen plus clean reference adds 73 requests and 4,672 clip inferences. If eight distinct masks (six search winners, S5 and isolated) are evaluated on **128 final fields × 512 clips**, the upper bound is 1,024 model requests and 524,288 clip inferences. Total upper bound is 7,241 requests and 922,176 clip inferences, plus adapter reference overhead. These are planning counts, not measured cost or a power calculation. Deduplication of coincident selected masks may lower actual final calls, but it cannot change query fairness during selection. The final analysis would compare per-pool paired risks using pools as the cross-pool units, with field variability within pools and dependence from shared clips kept explicit. Three seeds per method are selection replicates, not independent pools.

A prospective final KWS input window for this separate search study has **not** been approved or verified as unexposed. M9.6 used indices 3450–3961; the separate multi-BER workstream proposed 3962–4473 and reserved 4474–4889. This search work does not access or consume either window. The larger study therefore remains a **design**, with no frozen final manifest and no production one-shot run. Freezing a final configuration or calling its result confirmatory before a fresh final input partition, seeds, source hashes, and exposure audit are available would violate the scientific contract. A selection-only staged run can be planned after that audit; final evaluation must wait until all selections are sealed.
