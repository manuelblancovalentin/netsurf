# Stratified language-model storage-fault scaling design

## Status and inference target

This is a design for a later experiment. The three frozen 96-bit pilots have now passed exact stored-bit consumption, byte restoration, numerical-failure accounting and export gates, with their restricted-support results recorded in [manuscript evidence status](TRANSFORMER_MANUSCRIPT_INTEGRATION.md). This wider study is not a frozen fault-outcome campaign and has no effectiveness result. The pinned READY configurations are Pythia FP32 storage/FP32 computation, Pythia BF16 storage/FP32 computation, and Qwen BF16 storage/BF16 computation. Pythia native BF16 computation remains validation failed. The BF16-stored Pythia path faults original BF16 codes, then verifies the corresponding FP32 execution copy used by inference; these are distinct storage and computation representations.

The next sampling frame is **decoder-layer dense weights**, excluding embeddings, norms, biases, buffers, output heads and tied weights. Those excluded tensors are held clean by experiment design and are not described as protected. Safetensors metadata from the pinned checkpoints confirms the actual layer names and shapes below. This frame is wider than the 96-bit pilots, but it still does not support a full-model protection claim.

## Probability sample and bit identities

Use every layer and class as a stratum. From each actual matrix, sample **two distinct scalar-word ordinals uniformly without replacement**, using a frozen seed independent of the 96-bit pilot outcomes. On each selected word, sample one bit uniformly from each nonoverlapping class: sign; exponent; significand. This yields 96 Pythia words/288 candidate bits per stored precision and 392 Qwen words/1,176 candidate bits. The two Pythia configurations share sampled word ordinals to support a paired storage-precision diagnostic; their exact bit positions and arithmetic semantics remain format specific. Full tensor names, flat ordinals, original bytes, class, bit position, source file hash, selection seed and sampling order must be frozen before any fault inference.

For a tensor with `N_t` words, a specific bit in class `c` has inclusion probability `π = (2/N_t) × (1/m_c)`, where `m_sign=1`, `m_exponent=8`, `m_significand=23` for FP32 and `7` for BF16. All in-frame bits thus have known positive inclusion probability. Faulted-bit observations on the selected panel remain paired within sampled words and tensors. Inverse-probability weighting can describe a **single-bit finite-population mean** with uncertainty clustered at least by word and layer; it cannot turn a sparse panel's nonlinear, multi-fault protection result into whole-model risk. The three bit classes are separate strata in reports, with no unsupported numerical-displacement ranking for NaN/infinity mutations.

## Protection, fault exposure and costs

Keep susceptibility estimation, bit ranking, fixed-cardinality protection and Bernoulli fault generation separate. Supported initial policies are random allocation, encoded-position significance and task-matched exact isolated-bit scoring; a conditional selector, gradient or Hessian method requires its own verified resource and correctness gate. Every policy uses the same sampled panel and budget. The original bit population outside the panel is held unchanged; a panel budget is **not** a count of protected bits in the full model. Include clean, unprotected and full-panel logical-suppression controls. All selected-panel fault events are independent Bernoulli at a frozen `p`, persistent for one teacher-forced trial, and paired across policies. For panel size `M` and protected count `B`, record proposed exposure `Mp` and expected applied exposure `(M-B)p` plus realized proposed/applied/suppressed counts. A candidate planning family with unprotected panel exposure λ=1 and 4 would use `p=λ/M`, so budget arms change applied exposure at the same BER. These are planning levels pending the 96-bit performance gate, not a copied TinyML BER grid or a finalized test family. The much larger decoder frame would have expected faults `(N-B)p`; applying panel BER to every decoder bit would produce millions of faults and is outside this design.

Use deterministic teacher-forced WikiText-2 token NLL and perplexity, the existing 30-nat failed-token penalty, and a separate failed-token fraction. Preserve tokenizer, token sequence, context, stride and every scored target identity. A possible fresh validation selection slice starts after token 160 and a possible fresh test slice after the 96-bit pilot's scored tokens 1–256; exact slices and source hashes must be fixed after a new exposure audit, before selection or final inference. Shared or overlapping contexts are paired, not independent token replicates. Selection must seal before independent final fields. Report field-level paired uncertainty, per-layer/class variation, and honest limits from the sampled tensor frame. If the user later wants a full-decoder Bernoulli trial, it needs a new budget allocation, rare-event feasibility and estimator plan; no result from this panel substitutes for that trial.

Before freezing, measure full faulted inference and restoration throughput from the completed pilot receipts, then calculate requests, scored-token costs, RAM and disk for the larger panel and verify a feasible run duration. The pilots each completed 610 model requests and 143,647 scored target requests on their bounded 96-bit panels; these counts do not transfer directly to a 288- or 1,176-bit panel. Do not choose bit positions, strata, BER levels or final tokens to favor the observed 96-bit effects. Use fresh sampling and exposure identities. Do not use Pythia native BF16 compute, INT8 or INT4 without separate READY and exact representation gates.
