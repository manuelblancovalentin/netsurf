# Unresolved experiment ledger

## Submission boundary

The internal draft is complete using finalized evidence; none of the work below is a prerequisite for producing that draft. This ledger is a prioritized optional-week plan, not authorization to run, a frozen configuration, or a guarantee of statistical significance. No new model inference, masks, schedules, or research configurations were generated for it.

The supported empirical claim is condition-dependent effectiveness of the measured allocations on frozen checkpoints and cohorts. A universal claim about every static method, a general conditional-optimizer advantage, or causal attribution of observed crossovers to multi-bit interactions remains unsupported. Additional fault fields alone do not fix missing input/checkpoint replication or incomplete baselines.

## Grounded computational estimates

The finalized wide-run request receipts provide the following observed service-time scale. A request evaluates the complete fixed cohort under one fault field and protection mask. These are sums over concurrently executed shards, not elapsed campaign duration; they cannot be divided by an arbitrary worker count without measuring contention and resource limits.

| Model | Median request | 95th-percentile request | Actual faulted requests in the main wide grid | Summed request service |
|---|---:|---:|---:|---:|
| DistilBERT | 23.75 s | 27.79 s | 4,800 | 30.88 h |
| Pythia-160M | 11.56 s | 13.06 s | 4,800 | 15.68 h |
| Qwen3-0.6B | 32.55 s | 51.20 s | 4,800 | 49.35 h |

For planning only, multiplying 160 Pythia requests by the observed median/p95 gives 0.51/0.58 service hours. A similarly sized Qwen crossover replication with two BERs, 32 fields each, and two masks plus a shared unprotected control requires 192 faulted requests; the same arithmetic gives 1.74/2.73 service hours. These are rough compute scales, not confidence bounds on runtime. Different token lengths, cohorts, code instrumentation, contention, and export work can change them. New ranking construction is excluded because these examples reuse frozen masks. Disk and process-group peak memory for these prospective designs are not yet measured.

Observed mean TFLite score-construction seconds per build are ResNet-8 / KWS / ToyCar: global gradient 1.19 / 0.41 / 3.85; shared per-example absolute/positive computation 16.99 / 7.47 / 208.43; rank-two FKeras 5.58 / 1.43 / 11.42. These are the actual declared calibration cohorts, excluding model loading and exports. They are not portable timing guarantees. The full current TFLite grids took 14.07 / 6.31 / 3.24 hours of recorded coordinator elapsed time; coordinator peak RSS was 7.16 / 2.41 / 18.19 GiB, not the verified simultaneous sum across workers.

Large-model Hessian feasibility needs a separate bounded engineering receipt. If all eligible decoded parameters use float64, just one parameter-sized vector requires approximately 0.321 GiB for DistilBERT, 0.921 GiB for Pythia, and 4.440 GiB for Qwen. Those are arithmetic lower bounds from the eligible populations, not complete memory estimates: a Krylov basis, parameters, autodiff state, activations, and noneligible companion state add to them. TFLite's 25 observed HVPs and two eigenpairs cannot be extrapolated into an unmeasured large-model runtime claim.

## Statistical and interpretive safeguards

- Set a practically meaningful effect or precision target before choosing additional sample counts. Wide outcome variance is not itself invalid; uncertainty of a paired mean depends on the variance of paired differences and the correct independent unit.
- A field replication does not create a new input cohort, trained checkpoint, or ranking mask. Do not pool these uncertainty levels under one sample count.
- Preserve original multiplicity families for existing results. Any new confirmatory family must be prespecified. Nominal confidence intervals are not automatically multiplicity-adjusted intervals.
- “No resolved advantage” is not equivalence. An equivalence claim requires a prespecified negligible-effect margin and adequate precision.
- New independent fields on already inspected inputs can strengthen conditional fault-risk evidence, but those inputs must not be labeled untouched. Audited source identities, not dataset split names alone, establish exposure history.
- Do not attribute a method crossover to multi-bit interactions merely because BER is high. Encoding significance, calibration, surrogate error, loss censoring, task-metric alignment, and fault noise remain competing explanations unless isolated by a controlled intervention.
- Do not add activation faults or physical mitigation hardware to meet this week's deadline. They are distinct fault domains and would require separate lifetime, storage, event-accounting, and task-risk contracts. Their absence is a scope limitation, not evidence that parameter-only analysis validates an entire chip.

## Explicitly not proposed for the optional week

No new universal ranker, MCMC optimizer, importance-sampling campaign, architecture portfolio expansion, hardware-overhead estimate, or repetition of every existing grid is needed to complete the present manuscript. The highest-value additions are an independent-cohort check of a clear existing reversal and the missing censoring diagnostics, followed by numerically validated competing-method coverage if it is feasible. The present KWS conditional null should be reported, not hidden behind an additional favorable local study.
