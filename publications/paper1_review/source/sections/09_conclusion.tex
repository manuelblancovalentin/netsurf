\section{Conclusion}\label{sec:conclusion}
Choosing which stored bits of a quantized network to protect is neither a single-bit problem nor an intractable one. Under a protection mask, stored-bit faults behave like Gaussian noise on every weight, set by the exact moments of its unprotected bits, plus a few discrete events in the top-order bits; passed through the network, this description reproduced measured accuracy within half a point on 18 checkpoints it was not built on, and whether the preferred ranking changes with the fault rate on all of them. It explains what we measured on 24 checkpoints from 4,000 to 600 million weights. Protecting by bit position, as FORTUNE and the tier-first order of FKeras do, wastes the budget once faults are dense. Ranking by the per-example magnitude of the gradient effect, which mixes significance tiers, is a strong default. Rankings that exploit the sign of a flip help only at sparse faults, on some models, and can be worse than no protection, so no static ranking is guaranteed across fault rates, architectures and training states. Mechanisms differ in the same way: when redundant and check bits can fail too, codes are the efficient choice where faults are rare and triplication of ranked bits where they are dense, and triplicating the bits a gradient ranking chooses is never worse than triplicating the sign bits, and usually better. The analysis that decides between them is cheap, and should be made for each design.
